# A股波段交易每日作业手册

版本：D1.0  
生效日：2026-09-02  
策略基线：S1.1，状态 `frozen_pending_backtest`

## 1. 定位与边界

实时行情能力用于数据校验、候选跟踪、分钟触发和持仓保护，不代表策略已经获得统计验证。全市场候选必须来自完整、可回溯的收盘数据和当日时点股票池；不得用临时看到的热门股票代替全市场扫描。

助手负责读取、计算、筛选、生成交易卡、跟踪规则和复盘；用户保留最终下单决定并在券商客户端执行。系统不自动下单、撤单或转账。

## 2. 数据分层

| 数据层 | 用途 | 最低要求 | 失败动作 |
|---|---|---|---|
| 全市场日线 | T日收盘选股、MA/ATR/突破/量比/排名 | 完整A股时点股票池、至少120日、含中证500 | 当日不生成候选 |
| 实时分钟线 | T+1 9:45—10:30触发 | 时间戳≤90秒、分钟连续、VWAP可算 | 不开新仓 |
| 实时报价 | 持仓保护、价格上限、成交核对 | 交易时段时间戳≤90秒 | 只保留券商条件单，不人工追价 |
| 账户快照 | 仓位、现金、可卖数量、回撤 | 与券商逐字段一致 | 禁止新开仓 |
| 公告/财报日历 | 排除定期报告和不可控事件 | 信息发布日期可追溯 | 候选降为不可交易 |

东方财富公开接口可作为实时只读兜底，但不能单独证明“全A历史数据完整”；正式全市场扫描优先使用SuperMind批量导出或经过权限核验的Tushare数据，并保存每日原始快照和哈希。

## 3. 每个交易日的固定流程

### 08:50—09:20 盘前状态检查

1. 读取账户快照，核对总资产、现金、持仓、可卖数量和条件单状态。
2. 检查行情源、时区、交易日和最后数据时间；任何关键字段未知即禁止新开仓。
3. 读取上一交易日生成的候选清单，只保留满足公告、停牌、ST、上市天数和流动性要求的股票。
4. 根据当前权益重新计算每只候选的股数、初始止损、跳空压力和总仓位占用。
5. 生成事前交易卡；未锁定股票、触发价、最高允许价、数量和唯一止损的候选不得进入盘中监控。

### 09:20—09:45 开盘过滤

1. 观察候选开盘缺口，必须位于-1.5%至+3.0%。
2. 检查是否涨停无卖单、停牌、异常数据或价格超过T日收盘104%。
3. 只更新“可监控／失效”状态，不提前买入。

### 09:45—10:30 唯一入场窗口

1. 逐分钟计算价格、当日VWAP和数据新鲜度。
2. 某分钟收盘首次同时高于T日最高价和当日VWAP，信号才成立。
3. 最早按下一分钟开盘逻辑计划成交；不得使用信号分钟内的最低价美化结果。
4. 再次检查总仓位≤70%、单笔风险≤1.25%、单股限制、组合3%计划风险和6%跳空压力。
5. 多个信号同时出现时只按冻结分数排序，不临盘加入题材、盘口或主观强弱。
6. 输出一张最终交易卡交由用户决定并执行；10:30后未触发的候选当天失效。

### 10:30—15:00 持仓管理

1. 不再寻找新的入场机会，不追涨、不补仓。
2. 只监控已冻结的保护价、条件单状态、停牌和数据断线。
3. 盘中不因浮盈、盘口大单或单根K线随意上移/下移保护线。
4. 条件单触发后读取成交结果；未成交、部分成交或滑点异常必须进入偏差账本。

### 15:05—15:40 收盘处理

1. 固化当日日线、分钟线、基准和账户快照，记录数据源、生成时间和完整性检查结果。
2. 对持仓计算收盘R倍数、MA10、ATR20、持有天数和下一交易日保护价。
3. 只在S1规定的收盘事件发生时调整退出规则：首次+1R、首次+2R、8日时间止损或20日最长持有。
4. 更新交易、偏差、持仓和每日净值日志；未知字段留空，不估算成交价格或费用。

### 15:40—17:00 全市场候选扫描

1. 验证中证500市场开关：收盘>MA20且MA20>MA60；失败则输出“明日无新开仓”。
2. 在完整时点股票池上执行S1八项收盘条件和固定评分。
3. 保存全部通过/不通过原因，不只保存排名靠前的股票。
4. 输出次日候选清单，默认最多展示前5只，但不因此改变策略可持仓数量。
5. 为候选补齐公告、财报日期、价格上限、结构止损和风险股数，形成次日盘前输入。

## 4. 当前持仓退出后的恢复条件

两只存量股票退出并不自动要求马上买新股票。恢复新开仓必须同时满足：

1. 账户快照确认总仓位低于70%；
2. 中证500市场开关通过；
3. 上一交易日全市场扫描产生合格候选；
4. 实时分钟行情新鲜且完整；
5. 没有待处理的成交或规则偏差；
6. 事前交易卡和三问全部通过；
7. 候选不处于定期报告或不可成交状态。

没有候选时持有现金是合规结果，不为积累交易次数降低条件。

## 5. 周期性复盘

- 每周末：报告候选数、触发数、实际交易数、规则合规率、数据失败次数和当前回撤。
- 每10笔完整S1交易：计算胜率、平均盈利/亏损R、期望R、Profit Factor、MAE/MFE和费用偏差，但不据此临时改参数。
- 每月末：核对账户总账与券商交割单；检查最佳5%交易剔除后的收益集中度。
- 达到BACKTEST_ACCEPTANCE.md全部门槛并完成至少10笔无重大越界的执行模拟前，状态保持U0，风险参数不升级。

## 6. 自动化实现状态

1. 全A股票代码与时点状态缓存：已实现，SuperMind底库已通过1161/1161批、5802/5802代码验收；
2. 每日全市场日线增量更新及缺口检查：已实现，受首次底库门禁保护；
3. 中证500基准自动更新：已实现，并要求与全A日线同步提交；
4. 收盘候选扫描器与失败原因表：已实现，按日期保存全部股票的逐项结果；
5. 双层候选与S2环境路由：已实现；盘中候选分钟监视器尚未完成自动化；
6. 自动生成事前交易卡和收盘复盘报告：收盘研究摘要已完成，盘前交易卡仍需账户快照和分钟监视器；
7. 数据源失败时的明确停机状态：已实现 `FAILED_CLOSED`，底库不完整时为 `WAITING_FOR_COMPLETE_BASE`。

每日唯一入口为 `src/run_daily_pipeline.py`。候选始终标为“研究候选”，
只有次日账户快照、公告/财报、开盘缺口及09:45—10:30分钟触发全部复核后，
才可由用户在券商客户端决定是否下单。

首个全市场研究扫描器已加入 `src/scan_eastmoney_market.py`。它会建立代码池、抓取121根日线、检查覆盖率并运行冻结S1筛选；输出始终标记为研究扫描，公告日历和正式时点数据验收完成前不得直接作为下单依据。

收盘增量更新器已加入 `src/update_daily_incremental.py`。它不再逐股重拉121根
历史日线，而是按最近一次验收股票池批量读取当日收盘快照，将成交量由“手”
换算成“股”，并以99.5%覆盖率、日期一致性、重复运行和冲突检查作为写入门槛。
初始全量底库未完成时必须失败关闭，不能用局部底库启动自动候选扫描。

在这七项完成并验收前，系统可以可靠管理指定股票和验证分钟触发，但不能把“能查询任意股票”描述为“全市场自动扫描已经完成”。
